## 1. Intent & Why

Modern AI coding sessions lose context across runs, repeat debugging mistakes, generate unverified code faster than humans can review it (comprehension debt), and fail to compound learnings into reusable skills and structural guardrails.

**MyBrain** is built from scratch as an **Intelligence and Knowledge Control Center** that unifies:
1. **Persistent Knowledge & Graph Memory** (clean-room synthesis inspired by `garrytan/gbrain`),
2. **Trust Engineering & Michelin-Kitchen Specialization** (Lauren Tan / `@poteto`),
3. **Structured Agentic Engineering Disciplines** (Superpowers skills),
4. **Deterministic Software Factory Orchestration** (SSSF patterns: *"Agent proposes, code disposes"*), and
5. **Clean-Room Evidence Rigor** (REA — *Reverse Engineer Anything*: strict separation of Observations, Inferences, and Unknowns).

The core goal is a **closed iterative spiral** where every problem-solving cycle produces not only verified code, but also structured understanding, updated Knowledge Graph entries, and **new requirements generated by Reviewer/QA** that feed the next iteration.

## 2. Goals, Non-Goals & Anti-Goals

### Goals
- **Dual-backed Knowledge Vault:** Git-versioned Markdown pages (`vault/`) synchronized with an embedded PostgreSQL database (`@electric-sql/pglite` + `pgvector` + PostgreSQL Full-Text Search) using Reciprocal Rank Fusion (RRF) hybrid search and a typed Knowledge Graph (`entities`, `relations`, `chunks`, `evidence_ledger`).
- **Schema Packs:** Declarative YAML/Zod schemas defining entity types, frontmatter validation, and relation constraints (e.g., engineering domains, projects, incidents, requirements).
- **Skill & Intelligence Dispatcher (`RESOLVER.md`):** Thin harness, fat skills. Routes intents to Superpowers skills, Lauren Tan methodologies, Scout Understanding skills, Reviewer/QA Requirement-Generator contracts, and REA workflows.
- **Deterministic Software Factory:** Typed Zod handoff envelopes between isolated Kitchen Stations, explicit `writes:` path boundaries with automated rollback on violation, git worktree isolation per build task, and SQLite/PG trace logging (`factory_runs`, `station_events`).
- **Closed Iterative Methodology:**
  - **Scout / Research Station** enforces **Understanding Skills** (codebase mapping, Knowledge Graph lookup, invariant discovery, and REA artifact inspection when analyzing opaque binaries/bundles) *before* planning.
  - **Planner Station** runs `brainstorming` / `writing-plans` to emit atomic TDD plans.
  - **Builder Station** executes inside isolated git worktrees via `test-driven-development` and `subagent-driven-development`.
  - **Reviewer / QA Station** runs deterministic checks + `requesting-code-review` + `verification-before-completion` AND **generates typed `NewRequirement` items** (bugs, edge cases, tech debt, hardening rules, skill gaps) directly into the Requirements Backlog for Iteration N+1.
- **Dream / Gardening Cycle:** Post-iteration/scheduled synthesis that backlinks pages, refreshes embeddings, captures `systematic-debugging` root causes, prunes stale memory, and stages proposed `writing-skills` upgrades.
- **Hybrid Control Plane:** Single core engine exposed via `mybrain` CLI, MCP server tools (for Antigravity / Claude Code / Codex / OpenClaw), and a local Web Control Center UI.

### Non-Goals (v1)
- Multi-tenant cloud SaaS hosting, team RBAC auth, or distributed multi-node worker clusters.
- Blindly cloning `garrytan/gbrain` source code verbatim (clean-room TypeScript implementation guided by an explicit REA evidence ledger).
- Autonomous self-modification of MyBrain's own core harness, `RESOLVER.md`, or gate rules without human approval.

### Anti-Goals
- **Vibe-coding / prompt-only chains:** Agents must never own state transitions, bypass `writes:` boundaries, or declare completion without fresh exit-0 verification commands.
- **Unbounded Dark Factory on Day 1:** Default operating mode is **Light Factory** (autonomous execution with deterministic verification gates, plus human checkpoints at Plan Approval, Final Merge/Ship, and Self-Modification of Brain rules/skills).

## 5. Global Constraints

1. **Runtime & Toolchain (Verified on host):** Bun `>=1.4.4`, Node.js `>=24.x`, Git `>=2.50` on Windows (paths must use OS-safe `node:path` normalization; never hardcode `/` or `\` assumptions).
2. **Type Safety & Validation:** Strict TypeScript (`"strict": true`, `"noUncheckedIndexedAccess": true`). All cross-station envelopes, config files, schema packs, and MCP payloads are validated at runtime with **Zod**.
3. **Database Dual-Mode:** Embedded PGLite (`@electric-sql/pglite` + `@electric-sql/pglite/vector`) by default in `<vault>/.mybrain/pgdata` with zero external Docker dependency, behind a thin `DbClient` interface allowing external Postgres (`pg`) connection strings later.
4. **Embedding Optionality:** Must work **offline / zero-API-key** (`embeddingMode: "none"` -> FTS/BM25 + Graph retrieval gracefully degrades RRF weights) as well as with pluggable `EmbeddingProvider` adapters (e.g., local ONNX/Ollama or Gemini/OpenAI API).
5. **Trust Engineering:** Known deterministic commands (`tsc`, `bun test`, linters, git diff/worktree ops) execute as `kind: "code"` steps, never delegated to probabilistic LLM reasoning. Completion claims require fresh exit-0 command evidence.
6. **Light Factory Human Checkpoints:** Execution pauses for explicit human confirmation at: (a) Plan Approval before Builder starts, (b) Final Branch Merge / Ship, and (c) Any write to MyBrain's own `skills/`, `RESOLVER.md`, or verification gate definitions.

### 6.2 Subsystem 1 — `@mybrain/knowledge` (GBrain + REA Core)

- **Vault vs. Target Repo Topology:** MyBrain separates the **Brain Vault root (`--vault`)** from the **Target Problem/Code Repo root (`--repo`)**. A central Brain Vault can govern multiple target repositories (each scoped by `project_id` / `repo_path` on `pages`, `evidence_ledger`, `requirements_backlog`, and `factory_runs`), or `--repo` can point to `--vault` itself for self-hosted workflows. Keeping `--vault` independent prevents Builder git worktrees on `--repo` from colliding with Knowledge Vault or `.mybrain/pgdata` state.
- **Canonical Source of Truth & Sync Semantics:** **Git-tracked Markdown/YAML files under `vault/` are the single source of truth**; PGLite is a fast rebuildable index + vector/graph query engine (`mybrain reindex` rebuilds PGLite from `vault/` at any time).
  - `vault/pages/<entity_type>/<slug>.md`: Page content + YAML frontmatter (`id`, `type`, `title`, `tags`, `schema`, `projectId`, `confidence`, `relations[]`, `updatedAt`, `sources[]`).
  - `vault/ledger/<subject>/<id>.md`: Structured REA evidence entries (`OBS-*`, `INF-*`, `UNK-*`) in YAML frontmatter + narrative evidence body.
  - `vault/backlog/<req-id>.md`: Reviewer/QA generated `NewRequirement` items with frontmatter (`id`, `parentRunId`, `projectId`, `severity`, `category`, `status`, `acceptanceCriteria[]`).
  - **Write & Conflict Rule:** Every mutation API (`remember`, `relate`, `addEvidence`, `addRequirement`) writes the canonical `.md` file atomically first (`write-temp + rename`) and immediately upserts PGLite inside an in-process async mutex. On sync/startup, SHA-256 `content_hash` compares disk vs. PGLite; on external modification (e.g., `git pull` or manual edit), **disk wins** and PGLite re-indexes.
- **Database Schema (PGLite + `pgvector`):**
  - `pages`: `id TEXT PRIMARY KEY`, `slug TEXT UNIQUE`, `project_id TEXT`, `title TEXT`, `entity_type TEXT`, `schema_pack TEXT`, `frontmatter JSONB`, `content_hash TEXT`, `body_md TEXT`, `search_tsv TSVECTOR`, `updated_at TIMESTAMPTZ`.
  - `chunks`: `id TEXT PRIMARY KEY`, `page_id TEXT REFERENCES pages(id) ON DELETE CASCADE`, `chunk_index INT`, `content TEXT`, `token_count INT`, `embedding VECTOR(768)` (nullable when `embeddingMode: "none"`), `search_tsv TSVECTOR`.
  - `relations`: `id TEXT PRIMARY KEY`, `source_id TEXT REFERENCES pages(id) ON DELETE CASCADE`, `target_id TEXT REFERENCES pages(id) ON DELETE CASCADE`, `relation_type TEXT`, `weight REAL`, `evidence_ref TEXT`, `created_at TIMESTAMPTZ`.
  - `evidence_ledger`: `id TEXT PRIMARY KEY`, `project_id TEXT`, `target_subject TEXT`, `claim_kind TEXT CHECK (claim_kind IN ('observation','inference','unknown'))`, `statement TEXT`, `artifact_ref TEXT`, `verified_by TEXT`, `status TEXT`, `content_hash TEXT`, `created_at TIMESTAMPTZ`.
  - `requirements_backlog`: `id TEXT PRIMARY KEY`, `project_id TEXT`, `parent_run_id TEXT`, `source_station TEXT`, `severity TEXT`, `category TEXT`, `title TEXT`, `description TEXT`, `acceptance_criteria JSONB`, `status TEXT`, `content_hash TEXT`, `created_at TIMESTAMPTZ`.
- **Single-Owner Concurrency Model:** Embedded PGLite (`<vault>/.mybrain/pgdata`) enforces single-process ownership via an advisory PID/port lockfile (`<vault>/.mybrain/daemon.lock`). Standalone CLI commands acquire the lock directly if idle, or forward RPC requests over localhost/named-pipe when the `mybrain` local daemon (`ui` / `mcp serve` broker) is running. External `DATABASE_URL` (PostgreSQL + `pgvector`) bypasses single-process locking.
- **Hybrid Search & RRF Engine:** Runs SQL `ts_rank_cd` (BM25-style FTS) + cosine `<=>` vector similarity (when embeddings present) + 1-hop Graph Neighbor boost, fusing rankings deterministically with `score = sum(w_i / (60 + rank_i))` (`k = 60`).
- **Schema Packs:** YAML manifests validated via Zod defining allowed `entity_type`s, required frontmatter fields, and valid `relation_type`s (`gbrain-base` equivalent + `software-factory` pack for specs, plans, bugs, requirements, skills).

### 6.3 Subsystem 2 — `@mybrain/intelligence` (RESOLVER + Superpowers + Lauren Tan)

- **Thin Harness, Fat Skills (`RESOLVER.md`) & Skill Sourcing:** Deterministic trigger-table parser matching `(intent, phase, target_type, constraints)` -> ordered Skill bundle + Station contract. `SkillRegistry` resolves skills using prioritized mount paths:
  1. **Bundled clean-room `skills/`** inside MyBrain (`understanding/*`, `qa-requirements/*`, `lauren-tan/trust-audit`, `lauren-tan/gardening`, `gbrain/dream`, and standalone fallbacks), plus
  2. **Optional host skill mounts** configured in `mybrain.config.json` (e.g., local installed Superpowers & REA plugin directories) so installed host skills run natively without duplicating upstream prompt internals. External mounted skills remain read-only (`WriteGuard` never permits mutations outside `--repo` task allowlists).
- **Station Contracts (Michelin Kitchen):**
  1. **Scout / Research Station (with Understanding Skills):**
     - Skills: `understanding/codebase-map`, `understanding/knowledge-recall`, `understanding/invariant-extractor`, `rea/evidence-ledger` (invoked when target is binary/bundle/black-box).
     - Output Schema (`ScoutEnvelope`): `observedFacts[]`, `inferences[]`, `openUnknowns[]`, `affectedFiles[]`, `invariants[]`, `relatedKnowledgeIds[]`.
     - **Gate:** Cannot transition to Planner if `openUnknowns` marked `blocking: true` remain unresolved or unflagged.
  2. **Planner Station:**
     - Skills: `superpowers:brainstorming`, `superpowers:writing-plans`.
     - Output Schema (`PlanEnvelope`): `specPath`, `planPath`, `tasks[]` (with exact file scopes and `writes:` allowlists), `verificationCommands[]`.
     - **Light Factory Checkpoint:** Awaits human approval before Builder runs.
  3. **Builder Station:**
     - Skills: `superpowers:using-git-worktrees`, `superpowers:test-driven-development`, `superpowers:subagent-driven-development`, `superpowers:systematic-debugging`.
     - Output Schema (`BuildEnvelope`): `integrationWorktreePath`, `integrationBranch`, `taskResults[]` (`taskId`, `worktreePath`, `branchName`, `changedFiles[]`, `tddEvidence`). Each build task executes in its own isolated git worktree/branch (`factory/<run-id>/task-<n>`) and merges deterministically into the run integration branch (`factory/<run-id>`) before `VERIFY_CODE`.
  4. **Reviewer / QA Station (Closed-Loop Requirement Generator):**
     - Skills: `superpowers:requesting-code-review`, `superpowers:verification-before-completion`, `lauren-tan:trust-audit`.
     - Output Schema (`ReviewEnvelope`): `verdict` (`approved | changes_requested | blocked`), `verificationResults[]` (fresh exit-0 outputs), and **`generatedRequirements[]`** (`id`, `category`: `blocking_bug | edge_case | tech_debt | hardening_rule | skill_gap`, `priority`, `acceptanceCriteria[]`, `linkedFiles[]`).
     - **Iteration Spiral:** Blocking findings either cycle back to Builder in the same run (up to `maxFixCycles`) OR persist as `open` rows in `requirements_backlog` + `vault/backlog/*.md` to seed **Iteration N+1**.
  5. **Dream / Gardening Station:**
     - Skills: `gbrain:dream`, `lauren-tan:gardening`, `superpowers:writing-skills`.
     - Runs **after** `[HUMAN_APPROVE_SHIP]` (or standalone via `mybrain dream`, and captures `systematic-debugging` root causes if a run aborts/fails without touching target code): computes missing backlinks, updates chunks/embeddings, archives root causes as Knowledge Graph pages, and writes **staged skill/rule proposals** (requiring explicit human approval in Light Factory mode).

### 6.4 Subsystem 3 — `@mybrain/factory` (SSSF-Inspired Deterministic Orchestrator)

- **"Agent proposes, code disposes":** A pure TypeScript state machine (`FactoryRunner`) drives `SCOUT -> PLAN -> [HUMAN_APPROVE_PLAN] -> BUILD -> MERGE_TASKS -> VERIFY_CODE -> REVIEW_QA -> [HUMAN_APPROVE_SHIP] -> DREAM -> DONE`. At `[HUMAN_APPROVE_SHIP]`, the human chooses `merge_to_base` (fast-forward/merge + worktree cleanup) or `keep_branch_for_pr` (mark verified for manual PR/merge); rejecting Ship never corrupts `--repo` base or Dream memory.
- **Write-Boundary Guard (`WriteGuard`):** Snapshots git status/tree before each station executes; verifies every modified/created file matches the station's declared `writes:` glob allowlist and is NOT in `protected_files` (`skills/**`, `RESOLVER.md`, `.mybrain/gates.json` unless explicitly unlocked). Any unauthorized mutation is automatically rolled back (`git checkout` / file restore) and logged as a violation.
- **Deterministic Gate Runner (`kind: "code"`):** Executes shell checks (`bun test`, `tsc --noEmit`, lint) in the station's worktree, captures exit code + stdout/stderr digest + duration, and rejects state advancement on non-zero exit.
- **Trace & Event Store:** Persists `factory_runs`, `station_executions`, `gate_results`, and structured JSONL logs for live streaming to the CLI and Web Control Center UI.

### 6.5 Subsystem 4 — `apps/cli-mcp` & `apps/control-center`

- **CLI (`mybrain`):** `init`, `ingest`, `search`, `query`, `entity`, `ledger`, `run start|status|approve|resume`, `backlog list|promote`, `dream`, `mcp serve`, `ui`.
- **MCP Server:** Exposes JSON-RPC tools over stdio (`mybrain_recall`, `mybrain_search`, `mybrain_remember`, `mybrain_relate`, `mybrain_ledger_add`, `mybrain_ledger_list`, `mybrain_factory_status`, `mybrain_backlog_list`).
- **Control Center Web UI:** Local HTTP + WebSocket server backed by `@mybrain/factory` and `@mybrain/knowledge`, rendering:
  1. Factory Kitchen Swim-lanes (live station status, envelopes, gate outputs, approve/reject buttons),
  2. Knowledge Graph & Vault Explorer (pages, relations, REA evidence ledger filter),
  3. Iteration Spiral & Requirements Backlog (Reviewer/QA generated requirements ready to promote into next run).

## 7. Subsystem Decomposition (Implementation Plan Split)

Because MyBrain spans four cohesive yet independently testable layers, implementation is broken into **4 sequential plans**, each producing working, tested software:
1. **Plan 1 (`2026-11-15-phase1-knowledge-core.md`):** Monorepo bootstrap (`@mybrain/shared` + `@mybrain/knowledge`) — Vault Markdown sync, PGLite + `pgvector` schema, chunker, RRF hybrid search, Knowledge Graph, Schema Packs, and REA Evidence Ledger.
2. **Plan 2 (`phase2-intelligence-and-skills`):** `@mybrain/intelligence` — `RESOLVER.md` parser/dispatcher, built-in `SKILL.md` templates (Scout Understanding, Reviewer/QA Requirement Generator, Dream/Gardening), and Superpowers/Lauren Tan integration contracts.
3. **Plan 3 (`phase3-software-factory`):** `@mybrain/factory` — Deterministic ADW runner, Worktree manager, `WriteGuard` rollback protector, `kind: "code"` Gate Runner, Requirements Backlog loop, Trace DB.
4. **Plan 4 (`phase4-cli-mcp-and-control-center`):** `apps/cli-mcp` + `apps/control-center` — `mybrain` CLI, MCP server, and local Web Control Center UI.
